# F5A — modulo NPY e lease per versione

**Stato:** unità A implementata e testata su Windows; attende review indipendente e suite Linux PM. Nessun percorso produttivo `artifacts/indexing/deps` usa ancora il nuovo formato. Nessun modello, benchmark, container o commit dal worker.

## Superficie consegnata

- `core/colbert_store.py`: `ColbertStore(root)` espone `Mapping[str, ndarray]`, `.get()` standard (`None` sul chunk assente), `.token_count` da offset, `.verify_full_hashes()` esplicito e `.close()`. `ColbertStore.open_version(database_dir, version)` acquisisce prima una lease OS condivisa e la trattiene con il reader fino a `close()` o alla raccolta dell'ultimo riferimento. Ogni `__getitem__` apre NPY read-only con memmap, copia il solo intervallo del chunk e chiude la mappa prima di restituirlo. Il loader valida schema, dtype fp16, dimensione, file opachi, header NPY, byte size, copertura/offset e un solo documento per file; non materializza il corpus.
- `ColbertWriter(root, dim, parent=None, verified_parent_hashes=None, removed_docs=...)`: target nuovo, `add_document(doc_id, vectors)` scrive immediatamente **un documento** e libera i vettori quando il chiamante li lascia; `remove_document(doc_id)` elimina dal figlio anche un documento modificato diventato vuoto; `finish()` riusa i file dei documenti invariati con hard link, o `copy2` su errore, e scrive atomicamente `index.json`. Se c'è un padre, l'API **richiede una mappa esplicita di hash attestati** uguale alla sua tabella file prima di creare il target; non accetta un flag booleano. I file sono nominati con digest opaco del doc ID e contenuto; il nome non contiene path sorgente. Le statistiche distinguono byte nuovi, hardlink, copia e hash ereditati senza riverifica. Nessuna modifica in place dei file linkati, nessuna doppia scrittura NPZ/NPY.
- `core/writer_lock.py`: API additiva `try_version_lease(database_dir, version, exclusive=False) → VersionLease | None`; file persistente in `database/.reader-locks/<version>.lock`, fuori dalla directory cancellabile. Reader shared, retention exclusive **nonblocking**; `VersionLease.close()` e context manager. Il lock globale `.writer.lock` esistente non cambia. Lockfile non eliminato per evitare che due processi blocchino inode/handle diversi sotto lo stesso nome.

`index.json` ha `format=1`, `dtype="float16"`, `dim`, `chunks: chunk_id → {doc_id,file,start,stop}` e `files: nome_opaco → {sha256,bytes,rows}`. `ColbertStore` verifica metadati e header senza rileggere tutti i byte; `.verify_full_hashes()` è il passaggio profondo distinto. L'attestazione del padre può venire dal passaggio profondo oppure, in Unit B, da manifest pubblicato dopo aver verificato hash dell'index e coerenza della tabella file. Questa seconda strada **assume l'immutabilità** dei file già pubblicati e non rileva bitrot esterno nell'ordinario delta senza O(N) di lettura. Unit B deve rendere esplicita tale provenienza; la semplice copia della tabella non è una nuova verifica dei byte.

## Lease cross-process

La prima implementazione Windows con `msvcrt.LK_NBRLCK` è fallita nella prova reale: il secondo processo non poteva acquisire un read lock contemporaneo. È stata sostituita **solo per le lease di versione** con `LockFileEx` via stdlib `ctypes`, senza flag exclusive per reader e con `LOCKFILE_EXCLUSIVE_LOCK` per retention; `UnlockFileEx` rilascia la stessa regione. Su POSIX la primitiva è `flock(LOCK_SH|LOCK_NB)` / `flock(LOCK_EX|LOCK_NB)`. Il test Windows avvia due processi reali: entrambi leggono, l'exclusive fallisce dopo la chiusura del primo e riesce dopo la chiusura del secondo. Un test separato uccide il detentore e verifica il rilascio OS; su Windows il rilascio può richiedere un breve retry dopo `wait()`.

La lease protegge il **percorso fra richieste**, mentre open/copy/close protegge la singola slice. `open_version` rifiuta symlink/junction su database, versions, versione e colbert **prima e dopo** la lease; anche `.reader-locks` e il suo file rifiutano link. Unit B deve acquisire la lease prima di leggere qualunque artefatto della versione, verificarne ancora l'esistenza dopo averla ottenuta e tenere il `ColbertStore` nello snapshot; non chiuderlo durante il rebind se richieste precedenti lo usano. Il prune prende exclusive nonblocking sotto il writer lock, salta/logga i pinned e dichiara rimossa soltanto una directory davvero cancellata. Il codice per questo collegamento resta fuori da F5A.

## Test e limiti

Red: il primo run dei test ha raggiunto la prova cross-processo con `LK_NBRLCK` e non è arrivato a green; è stato interrotto perché l'asserzione iniziale leggeva stderr da un figlio ancora in attesa. La variante `LockFileEx` ha passato due reader simultanei. Green dopo rilievi review: `python -B -m pytest -q tests/test_colbert_store.py tests/test_writer_lock.py --basetemp eval/results/sidecar_readers_20260921/sandbox/pytest-phase5a-reviewfix2` → **27 passed**, exit 0. Coperti round-trip fp16, `.get(None)`, copia indipendente, token count, indice/header/path/offset corrotti, hash profondo, hardlink/copia fallback, documento rimosso o diventato vuoto, attestazione parent richiesta, guard symlink/junction versione, release dopo errore apertura, due processi shared/exclusive e crash. PM ha eseguito il checkpoint Linux antecedente ai rilievi: **25 passed**; la suite Linux finale sui fix è ancora da eseguire.

Il bound di memoria writer è il documento più grande passato ad `add_document` più la sua concatenazione temporanea e il batch encoder del chiamante, **non** una costante indipendente dalla dimensione del documento. Unit B deve alimentarlo progressivamente e non accumulare tutto in `_encode_chunks_to_points`. Il nuovo modulo non contiene cache di mappe né GC globale dei lockfile.

Per F6, `bench_delta._backup_database`, `_database_fingerprint` e `_restore_files` dovranno escludere/preservare `.reader-locks`: non cancellare il file lock mentre un server ha una lease. Prima di ripristinare le directory di versione, fermare/joinare i reader e rilasciare lo snapshot; il driver attuale non è ancora sicuro per quel ciclo di vita. Questa è una dipendenza del benchmark successivo, non una modifica F5A.
